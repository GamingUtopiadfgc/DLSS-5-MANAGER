DLSS 5 MANAGER - HOW THE GITHUB UPDATE FEATURE WAS ADDED
=====================================================

Purpose
-------
Previously, clicking the update badge opened a download website. The Settings
button checked for updates first, then opened that website on a later click.
Both buttons now use the same automatic download-and-install flow.

Files changed
-------------
1. Services\UpdateChecker.fs
   Finds a newer stable GitHub release, selects its installer, downloads it,
   verifies its SHA-256 digest, and starts the installation helper.

2. ViewModels\MainViewModel.fs
   Adds StartUpdate, tracks checking/downloading state, reports progress and
   errors, and prevents repeated update clicks while an update is in progress.

3. Views\MainWindow.axaml.fs
   Connects OnUpdateBadgeClicked and OnCheckUpdatesClicked to StartUpdate.
   Both handlers supply a callback that closes the application window after
   the installation helper has been started.

4. Views\MainWindow.axaml
   Disables the header update badge while checking or downloading. The Settings
   update button already used the CanCheckUpdates binding.

5. README.md
   Adds a short instruction for updating through Settings.

How it works
------------
1. The user clicks Check for updates in Settings or the header update badge.

2. The app requests release information from:
   https://api.github.com/repos/NODIX-TECH/DLSS-5-MANAGER/releases

3. It ignores draft and prerelease entries and selects the highest numeric
   version in the returned release list. It compares that version with
   UpdateChecker.CurrentVersion, currently "1.3.3".

4. If no newer version is found, the app displays its status instead of
   downloading anything. If GitHub cannot be reached, it displays that error.

5. For a newer version, the app looks for an asset named like:
   DLSS.5.MANAGER.1.3.7.exe

   The asset must also include a GitHub SHA-256 digest. Missing installer or
   digest information is reported in the update status.

6. The installer URL must use HTTPS and point to the official repository's
   GitHub release-download path.

7. The download streams into a uniquely named temporary executable:
   %TEMP%\DLSS5Manager-update-<unique identifier>.exe

   Progress is reported approximately every half second. The GitHub metadata
   request has a 12-second timeout; the download client has a two-hour timeout.

8. The app checks that the download is nonempty and, when a content length was
   supplied, that the byte count matches it. It also computes SHA-256 while
   downloading and compares the result with GitHub's digest. A mismatch stops
   the update before the installer is launched.

9. A hidden Windows PowerShell helper is started. It launches the existing
   Inno Setup installer with these arguments:

   /VERYSILENT /SUPPRESSMSGBOXES /NORESTART /SP- /DIR="<current app directory>"

   These request a quiet installation into the running app's directory without
   restarting Windows. Windows may still require an administrator/UAC prompt.

10. Once the helper process starts, the app closes its main window. The helper
    waits for setup to exit, attempts to delete the downloaded installer, and
    attempts to reopen the app at its original executable path.

Startup behavior
----------------
The existing startup check remains a notification-only check. It can show the
update badge, but it does not automatically install an update at launch.
Downloading and installation begin only after an update button is clicked.

Validation performed
--------------------
- Restored the existing NuGet dependencies after the first build reported a
  missing project.assets.json file.
- Built the project successfully with zero warnings and zero errors.
- Ran the release lookup through F# Interactive and confirmed that it returned
  version 1.3.7, its official installer URL, and a 64-character SHA-256 digest.
- Ran git diff --check successfully.
- Removed the bin and obj folders generated by validation.

Scope and limitations
---------------------
- The full installer was not downloaded or executed during validation. Actual
  replacement of installed files and relaunch were not end-to-end tested.
- The helper restarts the app when setup exits, even if setup fails or is
  canceled. It currently does not inspect the installer exit code or report
  installation errors back to the application.
- Starting the helper is not proof that the installer subsequently succeeded.
- Release discovery currently examines one GitHub API response page; it does
  not paginate the complete release history.
- This flow depends on the current Windows/Inno Setup packaging and versioned
  executable asset naming convention. It does not install the RAR asset.
- Keep CurrentVersion in Services\UpdateChecker.fs synchronized with the
  version fields in DLSS 5 MANAGER.fsproj for future releases.
- SHA-256 verifies that the download matches GitHub's published digest. It is
  not a malware scan or an independent publisher-signature verification.
- No changes to obfuscate.ps1 were needed for this feature.
